Why SketchLog

Designed for systems where raw telemetry volume becomes the bottleneck.

Traditional observability stacks often store more data than teams can afford to query. SketchLog keeps the operational answers while reducing the need to retain every raw measurement.

100M

events compressed into compact sketch summaries for fast operational queries.

93 KB

example compressed footprint for high-volume metrics instead of raw event storage.

O(1)

bounded-memory stream representation for predictable infrastructure costs.

CI

tested across Python, C++, WASM, Go, TypeScript, security, and docs workflows.

Platform

A compact telemetry layer that plugs into the tools teams already use.

SketchLog is not a replacement for every observability tool. It is a sketch-based layer for high-volume streams, designed to integrate with common infrastructure workflows.

01

Latency distributions

DDSketch-backed percentile tracking for p50, p95, p99, and tail-latency workflows with bounded memory.

02

Cardinality and frequency

Unique counting and event-frequency summaries for active users, error classes, and high-cardinality operational signals.

03

SLO and canary decisions

Smart SLO burn-rate evaluation and canary release analysis built on distribution diffing and anomaly signals.

04

Open telemetry paths

Prometheus export, Grafana dashboards and data source plugin, OpenTelemetry integration, and Collector exporter support.

05

Distributed mesh

Namespace-aware federation and anti-entropy sync for teams that need global sketch views across nodes.

06

Portable runtime

Python package, C++ core, WebAssembly runtime, TypeScript client, Go client, Docker demo, and Helm deployment path.
