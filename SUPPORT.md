# Support

## Where to get help

If you have a question, need help with installation, or want to discuss a feature request, please use the following channels:

*   **GitHub Discussions**: [Start a discussion](https://github.com/SBALAVIGNESH123/sketchlog/discussions) for general questions, feature requests, and architectural proposals.
*   **GitHub Issues**: [Open an issue](https://github.com/SBALAVIGNESH123/sketchlog/issues) to report bugs or reproducible crashes.

## Reporting a Bug

When filing a bug report, please provide:
*   Your OS and Python version.
*   The exact Sketchlog version you are using.
*   A minimal, reproducible example (MRE) if possible.
*   The full traceback of any errors.

## Security Vulnerabilities

If you discover a security vulnerability within Sketchlog (e.g., related to the standalone server, memory corruption in the C++ extension, or supply-chain issues), please do **NOT** open a public issue.

Instead, please privately report it to the maintainers or use the GitHub Security Advisory feature (if enabled).

## Support Boundaries

Sketchlog is an open-source project maintained by volunteers. While we aim to provide high-quality software, please note:
*   **No Commercial SLA**: Response times for general issues and discussions are not contractually guaranteed. The separate [security policy](SECURITY.md) publishes maintainer response and remediation targets for privately reported vulnerabilities.
*   **Community Support**: The primary support mechanism is community-driven. Maintainers will help as time permits.
*   **Supported Platforms**: We test CPython 3.10–3.14 on Linux, Windows, and macOS. Published native wheels cover the platform matrix in the [compatibility policy](docs/compatibility.md). Alternative implementations such as PyPy and architectures outside that matrix may use the Python fallback or may not be fully supported.
